# 09 · 人工干预点 → 自动化决策（含 99% 准确率协议）

> 来源：用户指令「你替我仔细分析替我决定，把人为需要干涉的全部改成自动化，把准确率提高到 99%」（2026-10-16）。
> 上游：`gates/gate_G1.md`（阈值唯一来源）、`08_g1_auto_omr_solution.md`（技术方案）、`automation_safety_rules.md`（**安全红线，不得自动化绕过**）。
> 定位：对**全流程**的人工干预点逐项做**自动化 / 保留**决策，并给出「99% 准确率」的**可测量**协议（P5：精度只由测量声明）。

## 0. 决策总览

| 类别 | 决策 | 理由 |
|---|---|---|
| G1 七项（线距/歪斜/裁切/顺序/文字/音符/密度） | **全部自动化** ✅ 已落地 | 原为「须人工补判」的 SKIP 项，是当前唯一阻塞 G2 的人工点 |
| G1-8 手写确认 | **自动化（fail-closed）** ✅ 已落地 | 默认按「不得自动 OMR」处理并自动分流 #65，**不再需要人工确认**；风险代理指标见 §3.3 |
| G2/G3/G4 人工点 | **本轮不动**（下阶段） | 属 OMR 之后的门，当前管线尚未到达；方案见 §4 |
| 和弦候选人工批准（P3 / F-5） | **保留**（故意控制） | `automation_safety_rules.md:39` F-5 明令「人工批准前禁固化」。自动化它 = 删除安全控制，**与用户目标（提高质量）相悖** |
| 门签核 / 风险登记 / 环境版本表 | **保留**（记录类） | 不是「判断」，是**责任记录**；自动化无意义（且 #22/#14 要求人工填） |
| G2-8 / G3-9「人工修正耗时」 | **不可自动化** | 该指标**测量的就是人工投入**，用于工具选型（#10）；自动化后指标失去意义 |

> **判定边界（我替你定的原则）**：自动化**判断类**人工点；**绝不**自动化**安全审批类**与**责任记录类**人工点。后者若也要自动化，等于拆掉项目的安全防线。

## 1. G1 人工点 → 自动化映射（已落地）

| 原 SKIP 项 | 自动化实现 | 判定 | 阈值（gate_G1.md） |
|---|---|---|---|
| G1-1 线距≥8px | oemer `Staff.unit_size`（换算回原像素） | PASS/NOTE/FAIL | ≥8px（≥6 放宽） |
| G1-2 歪斜角 | oemer `Staff.slope` → `atan` | 同上 | \|角\|<1°（<2° NOTE；≥2° FAIL） |
| G1-3 裁切完整性 | OCR 词框内容 bbox → 距页边余量 | 同上 | 余量≥1% 短边；触边 → FAIL |
| G1-4 页序/缺页 | 页眉/页脚 OCR 页码 → 序列校验 | 同上 | 缺页=0、重复=0（目录级） |

| G1-6 音符可区分 | oemer 符号层（notes/barlines/clefs/sfns/rests）非退化 | 同上 | 符号类别齐备且音符>0 |
| G1-7 信息密度 | MusicXML 计数（systems / measures） | 同上 | systems≤6、measures≤24 |

## 3. 自动化实现细节

### 3.1 引擎与钉版（可部署）
- OMR：**oemer 0.1.8** + `onnxruntime==1.20.0`（1.31 对老检查点负 pad 报错）+ `bbox.find_lines` 形状补丁（`plan/patches/`）。
- OCR：**pytesseract**（需系统 `tesseract-ocr` + `kor`/`chi-sim` 语言包）。
- 基线交叉校验（下阶段）：**Audiveris**（Java，`02_tool_selection_matrix.md:10` 既定基线）。

### 3.2 fail-closed 语义（关键安全设计）
- 引擎不可用/超时/输出不可解析 → 该项 **SKIP 并注明**，**绝不冒充 PASS**（P5）。
- 任一项 FAIL → 门结论 FAIL；NOTE → PASS_WITH_NOTES；SKIP 不计入通过项且单列「仍需人工」清单。

### 3.3 G1-8 手写确认的自动化
- 原实现：`classify_input.py:288` `"handwriting": "requires_human"（永不自动判定）`。
- 决策：**改为自动分流**——默认按「不得自动 OMR」处理（fail-closed），命中手写风险即自动进入 #65 人工录入路径；**不再阻塞等待人工确认**。
- 风险代理（下阶段接入，需标定）：五线谱线直度残差（印刷体谱线笔直，手写/拍摄畸变大）+ 符号检出率 + OCR 置信分布。

## 4. 后续阶段（G2/G3/G4 人工点）
- G2-3 节奏准确率（现「人工听回放」）→ 可用**小节级自动比对**（音长合计 = 拍号）+ MIDI 渲染差分；听感项保留为抽检。
- G4-6 结构可辨（现「人工勾选」）→ 段落能量/EQ 对比表已有（工具可自动产出），把勾选改为**阈值化自动判定 + 抽检**。
- G2-8 / G3-9 人工耗时 → **保留**（见 §0）。

## 5. 「99% 准确率」协议（可测量、不可空口声明）

**声明纪律**：任何「99%」必须附带 ①样本量 ②口径（合成/共识/真实标注）③日期 ④引擎版本。样本量 < 阈值（默认 100）→ 工具输出 `INSUFFICIENT_SAMPLES`，**禁止声明**。

| 层级 | 标定源 | 人工需求 | 可证明范围 | 状态 |
|---|---|---|---|---|
| L1 | **合成标定集**：程序生成注入已知真值（线距/歪斜/余量/系统数）的样本 | 零 | 测量→阈值→三态链路的判定一致率（可上 1000+ 样本） | 下阶段实现 |
| L2 | **双引擎共识**：Audiveris × oemer 独立判定；一致→高置信，不一致→NOTE（不放行 PASS） | 零 | 引擎可靠性 + 提升有效准确率 | 待 Audiveris 接入 |
| L3 | **真实标注集**：100+ 页真实谱面 + 独立标注 | 少量 | 真实世界准确率（唯一能声明「真实 99%」的口径） | 待采样 |

**安全红线（与准确率并列）**：
- `false_pass`（真值 FAIL → 自动 PASS）**必须为 0**；出现即判 `TARGET_NOT_MET`，不论一致率多高。
- 弃权（SKIP）单列 `coverage`，不混入一致率。
- 工具：`tools/checks/g1_accuracy.py --truth <标注> --report <--auto 报告> --target 0.99 --min-samples 100`。

**当前状态（诚实）**：仅 1 页种子（引擎自出，非独立标注）→ **INSUFFICIENT_SAMPLES**，**不宣称任何准确率**。已实测的余量（线距 2.3×、歪斜 6×）说明阈值设计留有充分相变裕度，但这**不等于**准确率数字。
