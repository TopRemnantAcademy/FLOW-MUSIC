# G1-1（静态）vs G1-1L（实测线距）一致性标定

> issue：`flow.237/FLOW-MUSIC#170`
> 测试：`music_rebuild_project/tools/checks/tests/test_g1_static_vs_measured.py`
> **本次未修改任何阈值，也未修改 `g1_auto.py`**。表中所有状态均来自只读调用
> `g1_image_quality.evaluate_path(path, cfg, auto=True)`；实测由无模型 CV 引擎给出
> （`oemer` 缺失时降级，不影响线距判据）。

## 1. 结论

| 语料 | 尺寸 / dpi | G1-1 静态 | G1-1L 实测 | 一致性 |
|---|---|---|---|---|
| `song01_preprocessed` | 2480×3508 / 300 | PASS | PASS（线距 18.0px） | AGREE ✔ 真值：二者皆 PASS |
| `blurred_true`（合成真糊） | 1240×1754 / 无 | FAIL | FAIL（线距 5.0px < 6px） | AGREE ✔ 真值：二者皆 FAIL |
| `song01_original` | 2480×3508 / 无 | FAIL | PASS（线距 18.0px） | **CONTRADICTION** → 交人工 |
| `session_upload` | 1357×1920 / 无 | FAIL※ | PASS※（线距 10.0px） | **CONTRADICTION**※ 语料不在库 |

读法：

- **好图不误挡、坏图不放行**这两条被钉住了：song01 预处理件两侧皆 PASS，真糊图两侧皆 FAIL。
- **打架的只有"缺 dpi 元数据"这一条**：像素和线距都够，静态代理却因为容器里没有 dpi 就判 FAIL。

## 2. 三条语料的判据原文

- `song01_preprocessed`
  - G1-1：`dpi=300.0≥300，短边=2480≥2400（线距≥8px 须人工/P30 验证）`
  - G1-1L：`线距=18.0px ≥ 8px（G1-1 子项，OMR 实测）`
- `blurred_true`（合成：线距 5px、7 组、无 dpi）
  - G1-1：`无法测得 dpi（容器=png）；不能证明 ≥ 阈值（短边现存 1240px）`
  - G1-1L：`线距=5.0px < 6px（OMR 实测不足）`
  - 谱线**还分得开、量得到**，所以是"真的坏"（FAIL），不是"量不到"（SKIP）。
    这两种形态都不该放行；但只有 FAIL 才算"实测侧也说了话"。
- `song01_original`
  - G1-1：`无法测得 dpi（容器=jpeg）；不能证明 ≥ 阈值（短边现存 2480px）`
  - G1-1L：`线距=18.0px ≥ 8px（G1-1 子项，OMR 实测）`
  - 与预处理件同像素、同线距，**唯一差别是 dpi 元数据**。
    这就是静态代理假阴性的最小可复现实证。

## 3. 关于"本上传图"（诚实说明）

`test_uploads/小小望楼_upload.jpg` **不在仓库内**。本测试不去造一张"长得像它"的图来充数：

- 语料命中优先级：`$G1_CONSISTENCY_UPLOAD` → `test_uploads/小小望楼_upload.jpg` →
  `02_source/upload/小小望楼_upload.jpg`；都没有就记 `missing`，对应用例 `skip`。
- 它在 issue 里的数据（1357×1920、无 dpi、G1-1 FAIL、G1-1L PASS 线距 10px）记在本文，
  但**没有**算进实跑结果。
- `song01_original` 是它的等价物：同为"无 dpi、像素与线距都达标"。要换成真身，把图放进
  `test_uploads/` 或给一次 `$G1_CONSISTENCY_UPLOAD=...` 重跑即可，代码不用改。

## 4. 测试怎么才算"红了"

只两条：

1. 真值断言不符 —— 好图被挡（假阴性）、坏图被放（假阳性）；
2. 已知矛盾 case 没被识别成矛盾（被静默判成 PASS/FAIL）。

矛盾 case 数量 > 0 **不会**变红：那是已知待裁事实，不是回归。
无真值的语料只允许落在 `INDETERMINATE` 或 `missing`，一旦被归类成 AGREE / CONTRADICTION /
BAND_DIFF 就算 bug 被抓 —— 那等于工具替人下了结论。

无 cv2 的环境（fast gate）里实测用例统一 `skip`：区分"测不了"和"测错了"。

## 5. 静态短边阈值是否随 G1-1L 放行而放宽 —— 建议（供 gate 评审，本次不改代码）

**建议：不动短边像素门槛，只给"缺 dpi 元数据"加一条有条件的豁免。**

先把两件事分开：

- **短边 ≥2400px** 是 A4@300dpi 的**图像学**等价物（8.27in × 300 = 2481px）。
  它回答的是"这张纸是多大扫描的"，不是"谱线够不够清楚"。
- **线距 ≥8px** 才是 OMR 的**可用性**判据：它直接量到下游要认的东西。

一个必须先承认的算术事实：**把短边门槛降下来，并不会让缺 dpi 的图过关。**
`short_relaxed` 已经是 1800px，而本上传图短边 1357px 连放宽带都不到。
所以"放宽短边阈值"解决不了 issue 里那个 case —— 真正的堵点是 `dpi is None → FAIL` 这一行。

因此分两层建议：

1. **`dpi is None` 的处理**（建议改，收益确定）
   - 有 G1-1L 实测线距且 ≥8px → 不因缺 dpi 直接 FAIL，记 `PASS_WITH_NOTES`，
     注明"dpi 未知（估值 1357px / 8.27in ≈ 164dpi，仅供参考）+ 实测线距 10.0px"。
   - 无 dpi 且 G1-1L 为 SKIP → **维持 FAIL**。测不到线距时静态侧是唯一证据，不能一起弃权。
   - 理由：缺 dpi 是**元数据缺失**，不是图像缺陷。用实测顶上它，比用代理指标一票否决更诚实。
2. **短边像素门槛**（建议不动，但正名）
   - 它现在干的是"下游渲染/裁剪够不够用"的活（G1-3 余量、G3 显示），
     那就把它明确写成**下游约束**，别继续当作 OMR 可用性的代理。改口径说明，不改数值。
   - 若将来要动它，请把 `clean_small` 这类"清晰但小"的页面一起评：
     1240×1754 的清晰页线距 12px 达标，却永远过不了 2400 短边 —— 这是"纸小"，不是"图糊"。

**不建议**让 G1-1L 单独决定放行：它依赖 CV/OMR 引擎，引擎不可用时是 SKIP 不是 PASS。
放行的前提永远是"实测侧已 PASS"，而不是"实测侧没说话"。

阈值改动须走 gate 评审并落 `08_qc/gate_config.json`；本次只出建议。

## 6. 证据边界

- 这是**一致性标定**：只说明"静态代理与实测在给定语料上如何分歧"，
  不说明"实测 PASS 的图 OMR 转录一定正确"。后者需要 L3 人工标注集，本测试不涉及。
- 合成语料只画五线谱骨架（水平谱线 + 小节线），够量线距，不代表真实谱面的复杂度；
  它的价值是把"线距 <6px 的真坏图"做成可复现的固定钉子。
- 判据状态一律如实保留：引擎降级、SKIP、missing 都不折算成 PASS。
